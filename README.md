# iWork 本地证据采集

从已登录的 iWork 工单页面采集正文、评论、附件与图片，结合钉钉群文件检索，在本地生成 `bugreport.md`。后续 Agent 从报告中的相对路径读取证据并分析根因。

```text
~/iwork_space/bug_261111_123456/
├── bugreport.md
├── 原始日志名.txt
├── 复现视频.mp4
├── 设备日志/             # 设备日志.zip 解压结果，成功后删除原包
├── files/                # 仅用于同名冲突，文件仍保留原名
└── .iwork/               # 快照、清单、OCR、来源与历史报告
```

目录格式为 `bug_<YYMMDD>_<数字Bug编号>`，日期为首次采集的本地日期。同一 Bug 补采使用同一个目录，旧报告存入 `.iwork/history/`。升级后自动把旧格式目录迁移为新格式，保留原日期、证据和任务进度。同名不同内容放入来源子目录，已有文件不覆盖；用户自己选取的原始文件不会被删除。

## 快速验证

要求 Linux、Python 3.10+、Chrome/Chromium 120+。Python 核心无需第三方依赖，扩展无需 npm 构建。

在项目根目录执行：

```bash
python3 -m iwork_collector doctor
python3 -m iwork_collector demo
```

`demo` 使用真正的文本文件和嵌套压缩包生成离线演示报告，不读取真实工单或钉钉消息。默认保存到 `~/iwork_space`；需要临时验证时：

```bash
python3 -m iwork_collector --root /tmp/iwork-demo demo
```

## 浏览器一次性安装

1. 保持项目目录位置固定。在该目录运行：

   ```bash
   python3 -m iwork_collector install-native
   ```

   该命令写入当前用户 Chrome、Chromium、Edge 的 Native Messaging 注册文件和启动脚本，不需要 sudo。项目移动后重新执行此命令。

2. 打开 `chrome://extensions`，启用开发者模式，选择“加载已解压的扩展程序”，选择本项目的 `extension/` 目录。
3. 固定扩展图标，打开 iWork 工单后点击扩展图标。扩展会自动展开详情、评论、附件和“视频/日志信息”等懒加载区域，等待页面渲染后采集；它会优先自动识别生产 iWork 的 `entityId`、详情字段、日志文件名和“见：【群名】钉钉群”线索。只有自动识别仍缺内容时，才在“设置”中配置 CSS 选择器。
4. 扩展显示当前文件、检索/下载/解压/校验阶段、耗时和已完成材料数；解压时显示实际展开量与文件数。下载没有字节回执时显示活动提示，进度条表示完成材料数，不表示当前文件下载百分比。可打开报告、打开文件夹、重试或取消。浏览器断开后，已开始的本地工作进程继续处理；需要浏览器下载的步骤等待重新连接。

0.1.12 升级后在 `chrome://extensions` 重新加载本扩展，再选已有任务点击“打开报告”：自动精简报告并整理可核验的旧单文件包装目录，不重新下载或解压大包。同名冲突、目录含其他文件或无法证明归档对应关系时保留原目录。单文件归档直接保存成员原名，多文件和真实子目录保留结构。旧目录整理使用硬链接，先保存新路径和来源关联，再清理旧链接，不额外复制大日志。

0.1.13 支持删除整个 Bug 文件夹后重新采集：在工单页点击“采集当前工单”，或对旧任务点击“重试”，会按当前日期创建新任务和目录，重新取得材料。已删除目录的完成状态和浏览器下载回执不再复用。若旧后台进程已重建目录但遗漏身份和快照，点击“打开报告”会根据该任务的匹配清单恢复元数据，保留现有日志。

0.1.15 升级后重新加载扩展，点击“打开报告”即可刷新已有报告：正文 `[LOG]`、`[视频/图片]` 改为 `[本地日志]`、`[本地视频/图片]`，直接列出相对于 `bugreport.md` 的 `./目录/` 或 `./文件名`，路径本身可点击，不再只显示群名或“见附件”。链接按材料来源关联，同名而来源不明、材料尚未取得时保留原线索；正文已列出的图片列表不再在材料区重复。评论中的 `@姓名` 会从 iWork 富文本提及属性中保留；旧采集已丢失的人名需要在工单页面重新点击“采集当前工单”，重新读取评论。

`bugreport.md` 面向 Agent，保留正文、字段、评论作者和回复关系、图片及时间线；材料只列顶层路径和最多 12 项视频/图片。报告不显示“采集缺口”，逐项路径、哈希、解压、检索及失败明细保存在 `.iwork/manifest.json`，任务状态照实保留，需要时再查。

同一工单下载失败后，点击“采集当前工单”或“重试”会重新执行失败的检索和下载，继续使用原 Bug 目录。仅打开扩展时的自动采集保持已有进度，不反复触发失败下载。

原包已下载但解压失败时，重试会先校验并复用 `.iwork/staging` 中的原件，不重新向钉钉下载。报告中待处理文件显示暂存路径和大小；未下载的原因、处理状态与哈希在完整清单中。该恢复路径已用数 GB 级真实日志包（解压后数千文件）验证。

0.1.10 支持复用本机已校验并登记在私有 `.iwork/recovery-cache.json` 的完整解压结果；正式任务重试时核对 Bug 编号、原包哈希、原名以及每个证据文件的哈希，通过硬链接接入原 Bug 目录。恢复来源不可由工单指定，内容变化、未登记文件和符号链接会被拒绝。移除缓存前须先取消对应登记。未登记恢复缓存时，按正常下载、解压流程执行。

大日志默认累计展开预算为 64 GiB、处理时间 30 分钟，最多 20,000 项、6 层归档；处理前与写入期间检查磁盘，保留至少 1 GiB。处理副本使用硬链接共享原包数据，避免多占一份大文件空间。空间不足或校验失败时保留原件并回滚未完成的解压结果，成功入库后清理原包和嵌套压缩包。可用 `archive_limits` 调整预算，正常使用无需配置。

固定扩展 ID：`oblbdhfcbmklhaebkonhfdidglfhinac`。不要移除 `manifest.json` 中的公钥，否则 ID 与原生宿主注册不匹配。

仅准备可检查的安装文件、不写用户浏览器配置：

```bash
python3 -m iwork_collector install-native --output ./dist/native-host
```

如果浏览器下载目录不是 `~/Downloads`，安装时明确指定（这是浏览器临时下载目录，不是最终的 `iwork_space` 报告目录）：

```bash
python3 -m iwork_collector --downloads-root /实际下载目录 install-native
```

下载交接路径必须属于工具登记的 `iwork-collector/<任务>/<文件任务>/<原名>`。不要把 `--downloads-root` 填成 `/iwork_space`；正确示例是 `/home/你的用户名/Downloads`。不要在浏览器中手工改变该次文件的目标路径；若企业策略强制“另存为”，应先完成保存，再按登记路径配置进行联调。

完成校验交接后自动删除浏览器中转副本及工具空目录，Downloads 不保留额外材料。新版启动时也清理旧版残留的工具空目录；其他下载文件、非空目录及正在使用的任务目录会保留。

## 工单页面配置

扩展设置支持编号、标题、正文、字段、评论、附件、图片、钉钉群和文件线索的 CSS 选择器。生产 iWork 页面还会在登录页上下文读取详情、评论树和变更记录接口，因此评论/时间线通常不需要单独配置选择器；真实页面不能访问时，通过 `tests/fixtures/iwork-ticket.html` 了解结构。

Bug 编号取明确的数字字段，或 `/bug/123456`、`/issues/123456`、`#/bug/123456`、`?bugId=123456` 等明确定位地址。生产 iWork 缺陷页的 `?entityId=123456` 也会自动识别。页面与 URL 编号冲突时拒绝采集；不会从任意标题数字猜编号。

页面采集会自动展开当前页面能识别的折叠区并等待异步渲染，并在 iWork 登录页面上下文读取已知的详情、评论树和变更记录接口；分页、历史评论、跨域 iframe、接口权限和特殊附件点击机制的未证实项保存在清单中。普通链接和 Cookie 保护下载由浏览器处理，特殊 POST/页面内 Blob 下载需要针对真实页面继续适配。

评论报告显示作者、评论 ID 和“回复谁”的链接，保留原文换行及 `@姓名`。评论及嵌套回复中的 HTML、JSONML、富文本图片会提取为独立证据，下载后显示在对应评论下；共享图片只下载一次。采集期间保持原工单标签页打开：图片在该页面的登录会话中读取，凭据留在页面中；跨域读取受限时使用浏览器下载，失败详情保存在清单中。

正文内可识别明确的“钉钉群：某某群”和文件名。未指定关联群、多个群无法确定、没有真实下载资源时，保留线索与缺口，避免取第一个结果。

## 钉钉与图片识别

钉钉接入使用本机 `dws` 和已有登录态，工具不会发消息、修改工单或主动要求登录。

- P1 指定群中提到的文件 → P2 群内关联文件 → P3 工单附件 → P4 URL。
- 优先级针对同一材料执行，不同日志、视频、图片分别收集。
- DWS 由本工程内置适配器自动执行：按群名精确解析会话，通过 `drive list`、有界目录遍历和 `chat message search` 找到文件。群消息附件先用 `chat +messages-mget` 重新读取原消息，核验唯一同名资源的类型和 ID。0.1.11 的消息 fileId 使用同一原消息的 `chat +messages-mget --download-resources --output-dir <相对目录>`，检查 `resourceDownloads` 的逐项成功、失败、类型、ID、路径和大小，不再由本工程改调 Drive 下载；消息含其他资源时停止，避免扩大下载。来自 `drive list` 的节点继续保留已知空间；mediaId 使用自身真实消息及会话上下文，不能把 fileId 改称 mediaId 重试。下载预算为 600 秒，保留完整脱敏 CLI 错误及实际返回的 trace ID。配置的 `dws_profile` 用于同一链路的全部调用。核验通过后按原名保存。
- 正文或评论明确写出的 `log_…` 即使缺少扩展名，也会生成文件检索任务；DWS 仅接受完整标识一致的实际压缩包名，按服务端返回的真实原名保存。API 补采的正文同样参与线索提取。旧版把日志标识误作群名且未取得文件的任务，会在重试时重建。
- 同一文件的机器人“日志已解析”消息会提供车端日志平台地址；DWS 未取得文件时，工具验证平台记录 ID 和完整文件名后尝试原包下载，失败后尝试平台已解析文件。文件保持原名和目录，嵌套压缩包继续解压。平台解析文件会标记为部分证据，不冒充原始压缩包完整副本。
- 精确群名和完整文件名足够建立检索任务，不需要用户提供日志网页接口。先尝试群消息中的原附件，再尝试该群文件；两条原包路径均未取得文件后，才使用日志平台副本。清单分别记录“已定位群文件”和“原文件下载结果”。
- 没有工单创建时间时仅查询采集前七天，并明确标为有界覆盖；不声称查遍全部历史。
- 原包或解析文件返回 HTTP 401/403，或下载前发现签名过期时，自动绕过缓存重新获取平台记录一次；只使用服务端返回的新授权，核对原包 MD5 和文件树身份，继续保持原名下载。若服务端仍返回旧授权，停止重复请求，并在清单记录自动重取结果和过期原因。
- 本工程自带 Linux x86_64 DWS runtime，目标机器仍需已有登录态。群原文件的在线下载、日志平台副本与签名续期行为，需在首次安装后于真实环境联调确认。
- 车端日志平台的下载网关路径属于访问凭据，不随代码分发：通过环境变量 `IWORK_VEHICLELOG_GATEWAY` 提供，或在项目根目录放置 `local.env`（内容为 `export IWORK_VEHICLELOG_GATEWAY='实际路径段'`，原生宿主启动脚本会自动加载，该文件不应提交到版本库）。未配置时解析文件下载会明确报告配置缺口。

可选配置写入 `~/iwork_space/.iwork/config.json`：

```json
{
  "dws_executable": "dws",
  "dws_profile": "实际组织ID:实际用户ID",
  "downloads_root": "/home/你的用户名/Downloads",
  "ocr_languages": "chi_sim+eng",
  "image_command": ["/绝对路径/图片观察程序"]
}
```

仅填写实际需要的键；不要照抄示例组织身份。项目包自带 Linux x86_64 的 DWS runtime，未在 PATH 中找到 dws 时使用它；`dws_executable` 可固定机器上的绝对路径。配置的 `dws_profile` 贯穿该客户端的全部查询和下载调用。

OCR 使用已安装的 Tesseract 和指定语言包；默认 `eng`。`image_command` 为可选的本地图像观察程序：以参数数组启动，最后一个参数是原图路径，标准输出为观察文本，不经过 shell。未配置时保留原图并报告缺口，不生成虚构图片描述。图片 OCR 发现的 URL 和文件名最多回流两轮；原图始终保存。

ZIP/TAR/GZIP 使用 Python 处理并验证完整性。7z/RAR 依赖本机相应工具；工具或密码不可用、缺卷、解压预算不足时明确报告失败，原包仅保留在全局暂存区供恢复。解压不执行任何成员文件。

## CLI 与恢复

```bash
python3 -m iwork_collector collect examples/snapshot.json
python3 -m iwork_collector status job_实际任务ID
python3 -m iwork_collector resume job_实际任务ID
python3 -m iwork_collector cancel job_实际任务ID
python3 -m iwork_collector list
```

本机 JSON 引用已有日志时，显式加入 `--allow-local`：

```bash
python3 -m iwork_collector collect 你的快照.json --allow-local
```

浏览器提交的 `local_path` 会被拒绝。文件清单和报告保存来源、哈希、解压关系、完整性和失败原因，报告不包含 Cookie、Authorization、签名链接凭证。短期下载链接仅保存在权限为当前用户可读的运行状态库中，目录中可能包含企业原始证据，整体复制时包含隐藏 `.iwork/` 子目录。

通常不需要常驻服务；原生桥接收到任务后启动独立工作进程，SQLite 保存进度。机器重启后可从扩展或 CLI 重试。若需要持续恢复已登记任务，可手动启动：

```bash
python3 -m iwork_collector daemon
```
